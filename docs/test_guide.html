Rover test guide: branch feature/rx-v2-firmware

This guide tells you how to load this branch on a rover with PlatformIO and a USB cable, and how to use it in the field. The commands run in a terminal in the repository folder, for example the VS Code terminal.

Quick start

  1. git fetch origin, then git checkout feature/rx-v2-firmware
  2. pio run -t erase (first load over V1.0 only; copy config.json off the USB drive first)
  3. pio run -t upload
  4. Full power-off: USB and vehicle power off, 5 s, on again
  5. pio device monitor -b 115200, type boot: expect BOOT rover-firmware 0.5.54
  6. Details: sections 3 (load), 6 (field steps), 7 (back to V1.0)

1. What changes, what stays

  • The ESP32 firmware changes: the main branch, plus rover mode (off by default), telemetry, a flash log, settings commands over USB, updates over USB with rollback, and the monitor role. README.md and docs/rover_guide.md list each change.
  • The STM32 app on the board stays as it is. The firmware runs the v1 STM32 app on the v1 link. The STM32 v2 app comes in a later step.
  • Outside rover mode, the rover moves as on main. The ODrive CAN code is the main-branch code, with no change.

2. Get the branch

PowerShell

git fetch origin

PowerShell

git checkout feature/rx-v2-firmware

3. First load over V1.0

This branch has a new partition table: two app slots for updates over USB, and a log area at 0x380000 to 0x3FFFFF. V1.0 never erased that area. So erase the flash once before the first upload.

The erase also removes the files on the rover's USB drive, with config.json, and the stored settings. If you changed a setting from its default, copy config.json from the rover's USB drive to the PC first. Section 6.2 tells you how to set the values again.

3.1 Erase

Connect the USB cable.

PowerShell

pio run -t erase

3.2 Upload

PowerShell

pio run -t upload

If a command stops at "Connecting", put the board in download mode: hold the 0 button, push and release RST, then release 0. Then do the command again.

3.3 Full power-off

After an upload through the download mode, a reset does not start the new firmware. Do a full power-off.

  1. Disconnect the USB cable.
  2. Switch off the vehicle power.
  3. Wait 5 s.
  4. Switch on the vehicle power and connect the USB cable.

4. Confirm the load

PowerShell

pio device monitor -b 115200

Type boot and push Enter. The answer starts with BOOT rover-firmware 0.5.54. Each second the board sends a HB line. packets=100 in that line shows that the STM32 app sends 100 packets a second. The start lines show STM link v1 for a v1 STM32 app.

Push Ctrl+C to close the monitor before you use a tool from section 6.

5. Defaults

After the erase, the firmware starts with the main-branch values:

SettingValue
kp, ki, kd5, 0, 0
steering_rate_kp, steering_rate_ki, steering_rate_kd0.02, 0.01, 0
steering_rate_max_dps90
CRUISE_THROTTLE, CREEP_THROTTLE1650, 1620
vehicleID, rx_channel3, 1
rover_enabledfalse (rover mode off)
imu_requiredtrue: if the IMU fails, the motors stay locked

docs/settings_def.json lists every setting with its unit, limits and default.

6. Field workflow (laptop, rover, USB cable)

The tools need Python 3.8 or later and pyserial. Install pyserial once:

PowerShell

python -m pip install pyserial

In the commands below, replace COM7 with the rover's port.

6.1 Live lines

Open the monitor as in section 4. The board sends your status lines, the HB line each second and its events.

6.2 Settings

In the monitor, type list, get <key>, set <key> <value> or save. A set acts at once. save keeps the values over a power-off. The same commands from a terminal:

PowerShell

python tools/rover_settings.py COM7 list

PowerShell

python tools/rover_settings.py COM7 set kp 5

PowerShell

python tools/rover_settings.py COM7 save

6.3 Log dump

The rover keeps a log in its flash. Close the monitor, then dump and decode the log to a file:

PowerShell

python tools/rover_log.py usbdump COM7 --out run1.jsonl

6.4 Later updates

Build the firmware, then send it over USB. This update needs no download mode and no power-off.

PowerShell

pio run

PowerShell

python tools/ota_upload.py COM7 .pio/build/lolin_s2_mini/firmware.bin --expect rover-firmware

The tool confirms the new image over USB. If the new image gets no confirm within 120 s, or stops before the confirm, the board starts the previous image. pio run -t upload also works, with the full power-off of section 3.3 after it.

7. Back to V1.0

PowerShell

git checkout main

PowerShell

pio run -t erase

PowerShell

pio run -t upload

Then do the full power-off of section 3.3. The erase removes the settings of this branch; V1.0 starts with its own defaults.

8. Known limits

  • The motor command goes out on the 12 ms timer of the main branch. On a bench board, 99 % of commands left within 10.7 ms of the sensor frame.
  • The log erases flash only while the axes are disarmed or the rover charges. The erased flash holds about 25 min of armed run at the default log rate of 20 Hz. After that, the log stops until the axes disarm.
  • After an upload through the download mode, only a full power-off starts the firmware.
  • This build did not drive an ODrive or a real rover before this test. The bench has no ODrive.
